# 公共资源网站采集项目备忘

## 1. 这类兼职项目的默认交付口径

- 默认只写采集代码，不接 MongoDB / MySQL / Redis。
- 默认不做上传接口，不做入库。
- 最终结果构造成 `dict`，测试阶段直接 `print`。
- 每个项目单独建文件夹，按网站名命名。
- `tests/`、`__pycache__/` 都放到项目目录里，不放公共目录。
- 代码风格尽量简约，优先能跑、好改、好交付。

## 2. 开工前先确认的资料

- 先看需求文档，确认到底要几个板块，不要自己扩。
- 再看字段汇总 Excel，字段名、字段类型、示例值都要核对。
- 如果客户给了模型文件，也要看一眼，确认哪些字段能走模型。
- 如果客户给了金额转换、附件结构、示例图片，也一起纳入。

## 3. 字段处理的核心原则

- 字段名以客户 Excel 为准，不要自创便捷字段。
- 字段类型也要以 Excel 为准，不要只看名字猜。
- 同名字段在不同模块里，内部结构不一定一样，要按各自 sheet 示例来。
- 示例值和类型列冲突时，优先记录下来，再按客户实际示例口径处理。
- `fileInfo对象` 这种是对象说明，不是外层字段名。

## 5. 这类公共资源网站常见采集套路

- 不要只看列表页 URL 变没变，要抓真实请求。
- 翻页很多时候不是前端换链接，而是接口里带 `pagenum`、`index`、`pageSize` 之类参数。
- 列表页常见是接口返回一段 HTML，再从 HTML 里提详情标识。
- 详情页常见是 `iid`、`noticeId`、`infoid` 这类 ID 在变化，其他参数基本固定。
- 能直接拼详情页就拼详情页，没必要硬走浏览器逻辑。

## 6. jnggzy 这次用到的分页经验

- 大部分栏目走 `/front/search.do`
- 国有企业采购走 `/front/assets/querySoaList.do`
- 农村产权走 `/front/getAgricultureList.do`
- 有些页面展示名和接口查询名不一致，必须做映射

## 7. 公共资源网站常见栏目映射思路

- 页面栏目名不一定等于最终业务板块名。
- 页面栏目名也不一定等于接口里的查询参数。
- 要区分：
  - 页面显示名称
  - 接口查询名称
  - 最终输出板块名称
- 例如这次项目里就存在：
  - `结果公示` -> 最终按 `中标公告`
  - `项目信息` -> 最终按 `招标公告`
  - `预中标公告` -> 有时归到 `候选人公告`，有时站内接口却查 `中标公告`

## 8. 模型接入经验

- 客户给模型，不代表必须直接 `import` 他们原文件。
- 更稳的方式是自己在主脚本里封装一层模型客户端。
- 模型输出字段名经常和项目字段名不一致，要自己做转换。
- 模型策略要提前定：
  - 是“模型优先，没值就空”
  - 还是“模型优先，没值回退规则”
- 本次 jnggzy 最终采用的是：默认开模型，部分字段先清空，再写模型结果。

## 9. 这次项目里确认过的字段口径

- `招标.procurementMethod` 走模型优先。
- `招标` 模块不要 `extra`。
- `候选人公告.extra` 保留，用来放模型补充信息。

  - 其他结果类 -> `2`

- `procurementUnit` 需要清洗联系人和电话后缀。
- `htmlContent` 需要 base64，且不能混入顶部提示文案、附件下载链接、下载地址。

## 10. 附件字段经验

- `中标.uploadFileUrl` 在这次 Excel 里是 `list[str]`
- `候选人公告.uploadFileUrl` 在这次 Excel 里是 `list[dict]`
- `招标.fileInfo` 是 `list[dict]`
- `采购意向.fileInfo` 也是 `list[dict]`
- 结论：不要因为字段名相近，就强行统一结构

## 11. htmlContent 处理经验

- 不能原样塞整页 HTML。
- 要去掉站点顶部提示文案，比如“尊敬的用户您好...”。
- 要去掉附件下载锚点。
- 要去掉裸露下载地址。
- 最后再 base64 编码。
- 这块很容易漏，后面遇到新站点要重点复查。

## 13. 测试习惯

- 至少要有模板字段测试，卡住字段集合别乱飘。
- 至少要有模型覆盖测试。
- 至少要有几个特殊字段测试：
  - `htmlContent` 清洗
  - `procurementUnit` 清洗
  - `announcementType`
  - `isUnion`
- 能跑 `pytest` 就跑。
- 至少再跑一次 `py_compile`。

## 14. 这类项目最容易出问题的地方

- 只看页面，不看真实接口。
- 把页面栏目名直接当最终业务板块名。
- 字段名对了，但字段类型不对。
- 同名字段结构被误统一。
- 模型开了以后，把规则值全覆盖掉却没意识到。
- README 还是旧口径，客户一看文档就误解。
- `htmlContent` 混进下载链接、提示语、无关头部内容。

## 15. 下次接同类项目的建议流程

1. 先看需求文档，确定模块范围。
2. 再看字段 Excel，整理四件事：字段名、字段类型、是否必填、示例值。
3. 打开网站，先判定列表页是否真翻页，确认真实接口。
4. 确认列表到详情的链路，是直接链接还是 ID 拼接。
5. 先写最小可跑版本，打出字典。
6. 再补字段清洗、模型接入、附件结构。
7. 最后补测试和 README。

- `uploadFileUrl` 结构为 `list[dict]`。
- 每个附件对象包含：`fileUrl`、`fileType`、`fileName`。
- `extra` 保留，用于放模型返回的候选人排序和项目编号。

### 模型处理

- 当前脚本内置了三个模型客户端：
- `BidModelClient`：招标公告。
- `TenderModelClient`：中标公告。
- `CandidateModelClient`：候选人公告。

模型使用方式：

- 开启模型后，模型能抽到的字段优先覆盖规则字段。
- 模型调用失败时不报错中断，保留规则提取结果。
- 模型不会改变最终字段模板。

### procurementMethod 规则

`procurementMethod` 只允许以下值：

- `单一来源`
- `邀请招标`
- `竞争性谈判`
- `询价`
- `竞争性磋商`
- `公开招标`

处理规则：

- 模型返回值在上面列表内，直接保留。
- 模型返回 `评定分离`、`挂牌` 等不在列表内的值，统一转成 `其他类型`。
- 模型没返回值，置为空字符串 `""`。

### htmlContent 处理

`htmlContent` 是清洗后的详情页 HTML，再做 base64 编码。

当前规则：

- 不抽正文。
- 不重新包 `<html><body>`。
- 不做乱码修复。
- 不改变编码链路。
- 去掉所有 `<a>` 标签本身，保留标签里的文字。
- 去掉底部 `我要参与` 按钮。
- 去掉底部 `关闭本页` 按钮和对应注释。
- 去掉底部 `澄清答疑` 按钮、隐藏弹窗和配套脚本。
- 去掉附件下载类链接，避免附件链接混入正文 HTML。

### 附件规则

附件统一从详情页原始 HTML 里提取，不从清洗后的 `htmlContent` 里提取。

当前支持：

- 常见后缀：`.pdf`、`.doc`、`.docx`、`.xls`、`.xlsx`、`.zip`、`.rar`、`.7z`
- `ztbpdfbybidguid`
- `downloadTemporary`
- `downloadfile`
- `download.do`
- `attach`
- `file`

排除规则：

- `操作手册`
- `操作说明`
- `供应商下载采购文件`

这些是平台使用说明，不算公告附件。

示例：

- 政府采购招标公告示例中，3 个 PDF 招标文件能提取，供应商操作手册会被排除。
- 政府采购中标公告示例中，`downloadTemporary` 类型附件能提取进中标 `uploadFileUrl`。
