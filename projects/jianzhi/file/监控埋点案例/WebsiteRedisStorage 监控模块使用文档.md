# WebsiteRedisStorage 监控模块使用文档

## 一、模块简介

`WebsiteRedisStorage` 是一个专门用于管理爬虫监控状态的存储模块，它将爬虫的运行状态数据存储在 Redis 数据库中，采用三级层级结构（省 -> 市 -> 网站）来组织数据。该模块支持数据的存储、更新、查询、统计和删除等完整操作，帮助采集人员实时掌握各爬虫的运行情况。

## 二、核心功能

### 2.1 数据存储结构

- 模块采用“省 -> 市 -> 网站”的三级结构存储数据：
  - 第一级（省份）：如福建省、江苏省、浙江省
  - 第二级（城市）：如福州市、厦门市、漳州市
  - 第三级（网站 + 业务类型）：使用 `"网站名称:业务类型"` 作为唯一标识
- 这种结构便于按地域维度进行数据组织和管理，支持快速定位特定区域的爬虫状态。

### 2.2 监控状态字段说明

每个爬虫状态包含以下关键字段：

| 字段名 | 类型 | 说明 | 取值 | 备注 |
| --- | --- | --- | --- | --- |
| `WasSuccessful` | 整数 | 脚本运行情况 | `1` 成功，`0` 失败 |  |
| `WebsiteError` | 整数 | 网站访问情况 | `1` 正常，`0` 异常 |  |
| `HasContent` | 整数 | 有无数据内容 | `1` 有数据，`0` 无数据 |  |
| `HasNewData` | 整数 | 有无新增数据 | `1` 有新增，`0` 无新增 |  |
| `IsValidData` | 整数 | 数据是否正常 | `1` 正常，`0` 异常 |  |
| `WebName` | 字符串 | 网站名称 | 例如 `"漳州市公共资源交易网"` |  |
| `BizType` | 字符串 | 业务类型 | 例如 `"建设工程-招标公告"` |  |
| `_last_updated` | 字符串 | 最后更新时间 | 格式：`YYYY-MM-DD HH:MM:SS` | 该字段在监控模块中自动生成 |

## 三、使用场景

### 3.1 场景一：单个爬虫状态上报

- 适用情况：某个城市只有一个爬虫在运行，或者只需要关注单一爬虫的状态。
- 操作流程：
  - 爬虫启动时初始化状态对象
  - 爬虫运行过程中收集各项指标
  - 运行结束后调用更新方法上报状态
  - 监控系统可以通过查询方法获取最新状态
- 典型用途：小型项目或单一数据源的监控。

### 3.2 场景二：多类型爬虫并行监控

- 适用情况：同一个城市的公共资源交易网有多个业务类型的爬虫，如政府采购、建设工程、土地交易、产权交易等。
- 操作流程：
  - 为每个业务类型创建独立的状态记录
  - 使用 `"网站名称:业务类型"` 作为唯一标识
  - 分别上报各业务类型的运行状态
  - 可以查询该城市所有爬虫的汇总状态
- 典型用途：大型交易平台的全面监控，区分不同业务线的健康度。

### 3.3 场景三：跨区域分布式监控

- 适用情况：需要在多个省份、多个城市部署爬虫，进行集中监控。
- 操作流程：
  - 按省市组织爬虫部署
  - 各地爬虫独立上报状态到中心 Redis
  - 监控平台按省市维度查看整体运行情况
  - 支持跨区域统计和对比分析
- 典型用途：全国性数据采集项目，省级或市级平台统一监控。

### 3.4 场景四：异常告警与故障排查

- 适用情况：需要及时发现爬虫异常并通知运维人员。
- 操作流程：
  - 定期轮询所有爬虫的最新状态
  - 检测 `WasSuccessful=0`（运行失败）或 `WebsiteError=0`（网站异常）
  - 触发告警通知（邮件、短信、钉钉等）
  - 根据状态字段快速定位问题类型
  - 查看最后更新时间判断是否长期未更新
- 典型用途：生产环境监控，保障数据采集的稳定性。

## 四、操作指南

详情可查看监控代码，括号内为对应方法名。

### 4.1 存储 / 更新状态（`update_website_data`）

- 何时使用：爬虫每次运行完成后，需要将运行结果记录到 Redis。
- 操作说明：
  - 如果该网站 + 业务类型的记录不存在，会自动创建
  - 如果已存在，会完全替换旧数据
  - 系统会自动添加最后更新时间戳
  - 必须提供省份、城市、网站名称三个定位信息
- 注意事项：
  - 省份和城市名称建议使用标准名称，如 `"福建省"` 而非 `"福建"`
  - 业务类型要统一规范，避免同一类型使用不同命名

### 4.2 查询单条状态（`get_website_data`）

- 何时使用：需要查看特定爬虫的最新运行状态。
- 操作说明：
  - 通过省份、城市、网站名称、业务类型四个条件精确定位
  - 如果忘记业务类型，可以不传该参数，系统会尝试匹配
  - 返回完整的监控状态数据

### 4.3 查询城市所有状态（`get_city_websites`）

- 何时使用：查看某个城市下所有爬虫的运行情况。
- 操作说明：
  - 只需提供省份和城市名称
  - 返回该城市所有网站 + 业务类型的记录列表
  - 可用于生成城市级别的监控报告

### 4.4 获取省份列表（`get_all_provinces`）

- 何时使用：需要了解系统当前监控了哪些省份。
- 操作说明：
  - 自动扫描 Redis 中的所有省份数据
  - 返回已存储数据的省份名称列表
  - 无需手动维护省份清单

### 4.5 获取城市列表（`get_cities_in_province`）

- 何时使用：查看特定省份下监控了哪些城市。
- 操作说明：
  - 提供省份名称
  - 自动扫描并返回该省份下的所有城市
  - 发现新城市时会自动纳入列表

### 4.6 统计信息查询（`get_website_stats`）

- 何时使用：需要了解整体运行健康度。
- 操作说明：
  - 支持全国统计、省份统计两种级别
  - 返回统计数值和百分比
  - 统计内容包括：总监控数、成功率、有内容率、有新增率、数据有效率
- 统计指标解读：
  - 成功率：爬虫运行成功的比例，反映程序稳定性
  - 网站异常率：目标网站无法访问的比例，反映网站可用性
  - 有内容率：成功采集到数据的比例
  - 有新增率：相比上次有新增数据的比例，反映信息更新频率
  - 数据有效率：数据格式正常的比例，反映解析逻辑正确性

### 4.7 删除状态记录（`delete_website`）

- 何时使用：爬虫下线、业务类型变更或测试数据清理时。
- 操作说明：
  - 需要提供完整的定位信息（省份、城市、网站名称）
  - 可选提供业务类型以提高删除精度
  - 删除后无法恢复，请谨慎操作

## 五、最佳使用建议

### 5.1 命名规范

- 省份名称：使用标准行政区划名称，如 `"福建省"`、`"江苏省"`
- 城市名称：使用标准市区名称，如 `"福州市"`、`"厦门市"`
- 网站名称：使用官方完整名称，如 `"漳州市公共资源交易网"`
- 业务类型：采用“一级类型 - 二级类型”格式，如 `"政府采购-招标公告"`

### 5.2 异常处理流程

#### 检测到 `WasSuccessful=0`

- 检查爬虫代码是否有 bug
- 检查服务器资源是否充足
- 查看爬虫日志定位具体错误

#### 检测到 `WebsiteError=0`

- 确认目标网站是否可访问
- 检查网络连接和代理配置
- 验证请求头是否被反爬

#### 检测到 `IsValidData=0`

- 检查网站页面结构是否变更
- 验证大模型解析逻辑
- 更新解析规则或模型

#### 检测到 `HasNewData=0`（持续多天）

- 确认网站是否真的有新数据发布
- 检查时间范围参数设置是否正确
- 验证去重逻辑是否过于严格
