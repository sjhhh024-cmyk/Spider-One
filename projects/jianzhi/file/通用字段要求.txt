 1. 字段名必须和客户 Excel 一模一样
     不能自创字段，不能改名，不能把一个字段换成自己觉得更顺手的名字。
  2. 字段值类型要稳定
     按客户示例来：

  - 普通文本字段就是字符串
  - uploadFileUrl / fileInfo 这类是列表就必须保持列表
  - 候选人公告里的附件列表元素是对象，不是纯字符串
 3. 空值统一处理

  - 空字段用 ""、[]、{} 这种空结构
  - 不能出现 Python 风格的 None
  - 也不能把字符串 "None"、"null" 塞进去

  4. 不存库，只构造字典
     这个项目只负责：

  - 请求列表
  - 进详情
  - 提取字段
  - 组装成最终字典
  - print 或示例输出
    不接数据库，不接上传。


  5. 模型默认开启
     客户给的模型要用上：

  - 招标模型
  - 中标模型
  - 候选人模型
    模型能覆盖到的字段，优先吃模型结果；规则提取主要做兜底。

 6. 附件字段分两套

  - uploadFileUrl：按客户模板要求放
  - fileInfo：对象列表，固定结构
      - fileUrl
      - fileType
      - fileName

  7. fileName 不能乱取
     附件标题优先取页面展示名，不是简单截链接最后一段。
  8. htmlContent 统一规则

  - 必须是 base64 编码后的 html
  - 解码后能直接打开并看到主体内容
  - 去掉所有 a 标签跳转能力
  - 去掉面包屑、按钮区、附件入口区等无关内容
  - 保留正文和必要底部元信息
  - 不能把正文误删
  - 不能出现隐藏正文导致“打开是空白”

  9. 同一公告要尽量保持原页面语义
     特别是复杂详情页，优先保留原模板结构，再灌真实值，不要随意拼成一张简化表，除非原页根本拿不到正文模板。
  10. 一级模块和二级栏目要分清

  - module_name 是一级模块
  - notice_type 是二级栏目
    现在配置了这两个，就只跑这一条二级栏目。
